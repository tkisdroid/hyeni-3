## 남은 작업 (우선순위)

### 1. 실기기 검증 — 이번 세션에서 못 한 유일한 항목

이 컴퓨터에는 `adb`·`JAVA_HOME` 이 없어 수행하지 못했다. **다른 컴퓨터의 첫 작업은 이것이다.**

대상 기기(AGENTS.md 안전 규칙): **A17(RFKL40DP73J) 부모 · razr(ZY22H9VTQD) 아이 · S25(R5CY521CFNZ)**.
세 기기 모두 현재 역할·세션을 유지하고 `npm run android:install:debug -- <serial>` 로 기본 사용자(0)에만 설치한다.
실제 로그아웃·역할 전환·재페어링은 하지 않는다. S25 는 고정 역할이 없으므로 역할 의존 검증 전에 CDP 로
`hyeni-api-session-v1` 의 role/familyId 를 먼저 확정한다.

확인할 항목(이번 이관이 실제로 화면에 반영됐는지):

- 언어를 en/ja 등으로 바꾼 뒤 **원시 message id 가 보이지 않는지**. 특히 콜드 스타트로 해당 화면에 바로 들어가
  namespace 누락을 확인한다(`AGENTS.md` 의 "라우트 namespace 누락 = 화면에 원시 message id" 항목).
  - 아이 하단 독 3탭·SOS 라벨(`core.childDock.*`)
  - 아이 위치/홈에서 위치 권한 다이얼로그(`shared.locationPermission.*`, `copyMode="child"`)
  - 온보딩의 같은 다이얼로그(`copyMode="formal"`)
  - 부모 홈 구독 카드 4줄(`parent.home.subscriptionCard.*`)과 **종료일 날짜 형식**
  - 부모 상세 화면 위 플로팅 AI 친구(PushShell 라우트에 `child` namespace 가 없어 `core` 로 옮긴 부분)
  - 아이 스티커 상세·대화 날짜 구분선·기기명(삼성 접두어)·소셜 로그인 제공자 이름
- 한국어에서 **기존 문구가 바뀌지 않았는지**(이관 시 화면 쪽 한국어를 정본으로 유지했다).
  특히 구독 카드 종료일이 `2026년 10월 1일까지 이용` 형태를 유지하는지.
- PWA: 설치 이름·설명이 언어를 따르는지(`public/manifests/manifest.<locale>.webmanifest`).
  ⚠️ 네이티브는 Service Worker 를 등록하지 않으므로 manifest 전환은 **웹/PWA 에서** 확인한다.

CDP 함정은 `AGENTS.md` 실기기 치트시트에 정리돼 있다(디자인 판정은 `exec-out screencap`, `awaitPromise` 긴

### 2. Worker·Pages 배포

이번 세션은 코드만 올렸고 **배포하지 않았다**. 웹에서 다국어를 확인하려면 Pages 배포가 필요하다.

- Worker 변경 없음 → Worker 배포 불필요.
- Pages 배포는 `worker/.env` 의 토큰을 **저장소 밖 디렉터리**에서 주입해 실행한다
  (저장소 안에서는 루트 `.env` 의 D1 전용 토큰이 자동 로드돼 실패한다). 상세는 `AGENTS.md` "Worker 배포 자격".

### 3. eventCompanionPrompt — 계획 결정이 먼저 필요 (스캐너 밖 잔여 결함)

**이것이 유일하게 남은 문구 결함이고, 코드로 바로 풀 수 없다.**

`aiBuddyNudge.nextEventNudge` 의 `fullLine` 꼬리말이 `eventCompanionAsk` 에서 오고 아직 한국어다.
이 값은 hook(`useAiBuddyNudge`) 을 거쳐 흐르므로 literal 스캐너의 taint 추적 밖이고, allowlist 에 남기면
`stale_allowlist` 로 실패한다 — 그래서 문서에만 기록돼 있다.

뿌리 문제:

- `src/transform/eventCompanionPrompt.ts`(문구 152개)·`src/transform/childBelongings.ts`(59개)는
  **한국어 일정 제목 키워드 매칭이 본체**다. 제목이 베트남어면 표가 아무것도 맞히지 못한다.
- `worker/shared/aiEventContext.js` 와 키워드 동기화 계약이 있다(`tests/eventCompanionPrompt.test.ts` 가
  키워드 표와 `resolveEventCompanionKind` 를 대조한다 — ask 문구는 대조하지 않는다).

정해야 할 것: locale 별 키워드 표를 둘지 / LLM 에 분류를 맡길지 / 이 기능을 한국어 locale 에만 노출할지.
TK 결정 뒤에야 구현할 수 있다.

## 이번 세션에서 배운 함정 (같은 실수 반복 방지)

`AGENTS.md`·`CLAUDE.md` 에 반영해 뒀다. 요약:

1. **문구 이관 전에 `locales/` 를 먼저 검색한다.** 위치 권한 고지는 이전 task 가 21개 id 를 10개 언어까지
   번역해 두고 컴포넌트를 재배선하지 않아, 화면은 한국어인데 카탈로그에는 아무도 안 읽는 번역이 있었다.
   `validate-catalogs` 는 미사용 id 를 잡지 못한다.
2. **namespace 는 그 컴포넌트를 쓰는 모든 라우트 그룹에 있어야 한다.** 공용 다이얼로그는 `shared`,
   ChildShell+PushShell 양쪽에 뜨는 AiBuddyFab·ChildDock 은 `core`.
3. **`intl` 을 받는 transform 은 `withDefaultIntl` 계약**을 따른다. 마지막 인자에 `providedIntl?: IntlShape`,
   본문 첫 줄 `const intl = withDefaultIntl(providedIntl)`. 선택 인자를 중간에 끼우면 기존 호출의 숫자 인자가
   intl 자리로 들어간다.
4. **message id 는 정적**이어야 한다. 템플릿·element access 조립은 `unclassified_dynamic_id` 로 막힌다.
5. 이 계약에 새로 들어오면 `node scripts/i18n/build-catalogs.mjs` 로 `legacyKoreanMessages` 를 재생성하고
   `tests/defaultIntlFallback.test.mjs` 의 id 수·importer 수 기대값을 갱신한다.
6. 브랜드명처럼 의도적으로 영어와 같은 값은 `scripts/i18n/audit-task8-locales.mjs` 의
   `identicalEnglishAllowlist` 에 근거와 함께 등록한다.
7. **locale JSON·`descriptions.json` 은 정렬돼 있지 않다.** 새 키는 뒤에 append 한다(재정렬하면 diff 가 파일
   전체로 번져 검토가 불가능해진다).
8. 원문 정규식으로 문구를 지키던 테스트는 **catalog 계약으로 옮기면 더 강해진다**(10개 언어 실재·한국어 잔존 0·
   브랜드 표기까지 검증).
