# 역할별 전체 동선 안정화와 1.4.1 출시 설계

## 1. 목표

가입·로그인·온보딩부터 부모·아이·공동보호자·선생님·프리미엄 흐름까지 실제 사용 동선을 점검하고, 사용자가 누른 행동의 이름과 다음 화면이 일치하지 않는 문제를 고친다. 기존에 검증된 부모용 글래스 UI와 아이용 3D 캐릭터 UI는 유지하며, 확인된 결함만 최소 범위로 수정한다.

이번 출시의 대표 결함은 아이 홈의 `길찾기 출발!`이 지도를 열지 않고 설명용 `RouteSheet`를 먼저 여는 이중 동선이다. 버튼·지도 노드·혜니 말풍선 중 길찾기를 뜻하는 진입점은 모두 한 번에 `/route`로 이동해야 한다.

## 2. 선택한 접근

### A. 동작 중심 최소 수정 — 채택

- 버튼 문구가 약속한 결과를 첫 탭에서 실행한다.
- 조회 실패는 오류를 숨기지 않고 같은 화면에서 재시도할 수 있게 한다.
- 역할과 활성 아이 식별자를 기존 정본대로 유지하고 첫째 폴백을 추가하지 않는다.
- 자동화 감사에서 정상으로 확인된 화면의 레이아웃과 카피는 바꾸지 않는다.
- 확인된 결함마다 회귀 테스트를 먼저 실패시킨 뒤 최소 구현한다.

이 방식은 사용자가 요청한 빠른 마무리와 현재 실사용 안정화 단계에 가장 잘 맞는다.

### B. 역할별 화면 전체 재디자인 — 제외

57개 화면의 모바일 시각·접근성 기준선이 통과한 상태에서 전체 디자인을 다시 바꾸면 검증 범위와 회귀 위험만 커진다.

### C. 길찾기 한 건만 수정 — 제외

가장 눈에 띄는 문제는 해결하지만 가입부터 결제까지 전수 확인해 달라는 요청과 출시 안정성 요구를 충족하지 못한다.

## 3. 행동 계약

### 3.1 아이 홈 길찾기

```text
다음 일정 지도 노드 / 혜니의 다음 일정 말풍선 / 길찾기 출발!
  → /route
  → RouteView가 본인 아이와 다음 일정 목적지를 결정
  → 현재 위치·저장 장소·일정 데이터를 기반으로 지도와 경로 상태 표시
```

- 다음 일정이 없는 지도 노드·혜니 탭은 기존처럼 오늘 시간표를 연다.
- 다음 일정이 있는 세 길찾기 진입점은 `RouteSheet`를 거치지 않는다.
- 위치 또는 목적지가 없으면 별도 홈 안내를 띄우지 않고 `RouteView`의 정직한 빈 상태와 복구 행동을 보여 준다.
- 출발·도착 알림은 홈의 기존 원탭 상태 버튼을 유지한다. 길찾기 중간 시트 제거로 안전 기능이 사라지지 않는다.

### 3.2 역할별 오류와 접근 제어

- 부모 전용 기능은 부모 역할과 전역 활성 아이를 그대로 사용한다.
- 아이 기능은 본인 `user_id`와 일치하는 child member만 사용한다.
- 공동보호자는 서버가 허용한 범위만 표시하고 기본 보호자 전용 변경을 우회하지 않는다.
- 선생님 모드는 현재 프로덕션 게이트를 유지한다. 준비 중 화면을 기능 오류로 간주해 임의 활성화하지 않는다.
- 인증·가족·일정·위치 조회 실패를 빈 데이터로 위장하지 않고 기존 오류·재시도 UI를 보존한다.

## 4. 화면과 문구

- 부모 모드는 기존 라벤더 글래스 디자인, 존댓말, 최소 44px 터치 영역을 유지한다.
- 아이 모드는 기존 3D 혜니 캐릭터, 반말, 큰 원탭 행동을 유지한다.
- `길찾기 출발!`처럼 결과형 문구는 설명 시트가 아니라 실제 결과 화면을 연다.
- 새로운 장식, 배지, 모달 또는 불필요한 성공 토스트는 추가하지 않는다.
- 혜니 말풍선은 현재 한 줄 표시 계약을 유지한다.

## 5. 테스트와 검증

- 길찾기 세 진입점이 모두 `/route`로 이동하고 다음 일정 없음 분기는 시간표를 여는 회귀 테스트
- 역할별 라우트·조회 상태 매트릭스
- 앱 전체 Node 테스트와 Worker 테스트의 실패 수 요약 확인
- TypeScript 앱·Worker 타입 검사와 프로덕션 빌드
- 390×844 기준 전체 브라우저 QA, PWA 설치·오프라인·업데이트 QA
- Capacitor 동기화, Android unit test·lint·debug 조립
- 연결된 실기기가 있으면 세션을 보존하는 `--user 0 -r` 설치만 수행

실사용 계정 로그아웃·역할 변경·재페어링, refresh token 회전, 프로덕션 D1 파괴 변경은 하지 않는다.

## 6. 출시

- 앱 버전은 `1.4.1`, Android/iOS 빌드 번호는 `13`으로 맞춘다.
- 최신 커밋으로 빌드·검증한 뒤 `main`에 한국어 커밋을 만들고 원격 `main`으로 푸시한다.
- Pages는 새 `dist`를 배포하고 배포 URL과 소스 commit을 기록한다.
- Google Play용 AAB는 clean worktree와 최신 commit SHA 조건을 만족한 상태에서만 생성한다. 서명 비밀번호는 사용자가 직접 입력하며 에이전트가 자격 파일을 읽지 않는다.
- Worker 소스가 바뀌지 않으면 Worker를 불필요하게 재배포하지 않는다.
