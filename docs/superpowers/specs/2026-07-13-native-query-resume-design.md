# Android 포그라운드 조회 복구 설계

## 배경과 관측 근거

2026-07-13 S25 부모 앱에서 혜니의 실시간 위치와 오늘 경로가 보이지 않는 것처럼 보였다. 같은 시점의 확인 결과는 다음과 같다.

- S25 부모 세션과 razr 아이 세션은 같은 가족에 정상 연결돼 있었다.
- 가족 구독은 `active` 프리미엄이었고 위치 조회 권한도 정상 판정됐다.
- razr 위치 업로드와 D1의 현재 위치·오늘 경로 이력은 계속 증가하고 있었다.
- 백그라운드 상태의 S25 WebView 조회는 완료되지 않았지만 기존 `MainActivity`를 포그라운드로 전환하자 즉시 HTTP 200으로 완료됐다.
- 포그라운드 화면에는 실시간 위치와 08시 이후 오늘 경로가 정상 렌더링됐다.

따라서 서버 데이터, 위치 업로드, 구독 판정 또는 지도 렌더링 실패가 아니라 Android WebView가 비활성 상태에서 멈춘 조회를 앱 복귀 시 확실히 재개하지 못하는 생명주기 연동 누락이 직접 원인이다.

현재 `QueryProvider`는 `refetchOnWindowFocus: true`를 사용하지만 Capacitor의 `appStateChange`를 TanStack Query 조회와 연결하지 않는다. Android 앱의 활성 상태와 브라우저 `visibilitychange`는 같은 신호가 아니므로 다른 기기의 위치·채팅·일정 화면에서도 같은 오해가 생길 수 있다.

## 목표

- Android 앱이 실제 백그라운드에서 포그라운드로 돌아올 때 현재 화면에서 사용하는 서버 조회를 한 번 갱신한다.
- 위치 화면에 국한하지 않고 채팅, 일정, 가족 정보 등 TanStack Query를 사용하는 모든 현재 화면에 같은 보호를 적용한다.
- 조회 전에 기존 네이티브 세션 채택 절차를 완료해 오래된 WebView 토큰으로 요청하지 않는다.
- 기존 캐시를 유지한 채 백그라운드 재조회하여 빈 화면이나 전체 새로고침을 만들지 않는다.
- 중복 생명주기 이벤트와 React StrictMode 재마운트에서도 중복 조회를 제한한다.

## 비목표와 안전 경계

- 전체 WebView 새로고침이나 라우트 재마운트를 하지 않는다.
- 미사용 캐시까지 모두 조회하지 않는다.
- 위치 즉시 요청, 원격 벨·원격 청취, AI 호출, 크레딧 소모, 결제 복원 같은 mutation을 이 기능에서 실행하지 않는다.
- refresh 토큰 원문을 읽거나 출력하거나 외부에서 회전시키지 않는다.
- 위치 전송 주기, 서버 API, D1 스키마 및 백엔드 Worker는 변경하지 않는다.
- 웹·PWA의 기존 `visibilitychange` 동작은 변경하지 않는다.
- 새 라이브러리를 추가하지 않는다.

## 선택한 구조

### 1. 생명주기 상태 조정기

`src/queries/nativeQueryResume.ts`에 프레임워크와 분리된 작은 상태 조정기를 둔다. 조정기는 최초 활성 상태를 기준값으로만 저장하고 `inactive -> active` 전환에서만 전달받은 복구 작업을 실행한다.

조정기는 다음 규칙을 지킨다.

- 최초 상태가 이미 `active`인 앱 시작은 일반 query 마운트가 처리하므로 추가 재조회를 하지 않는다.
- `inactive` 이벤트는 상태만 기록하며 네트워크 작업을 실행하지 않는다.
- `inactive -> active`에서만 복구 작업을 실행한다.
- 연속된 `active` 이벤트는 무시한다.
- 복구 중 새 `inactive -> active` 전환이 들어오면 동시 실행하지 않고, 현재 작업이 끝난 뒤 대기 중인 전환을 정확히 한 번 실행한다.
- 정리된 조정기는 이후 이벤트를 실행하지 않는다.

이 단위를 순수 의존성 주입 형태로 만들어 Capacitor나 React 없이 상태 전환과 single-flight 동작을 단위 테스트한다.

### 2. NativeBootstrap 연결

`NativeBootstrap`에 Android 전용 effect를 하나 추가한다. effect는 `@capacitor/app`의 현재 상태와 `appStateChange` 리스너를 조정기에 전달하고 정리 시 리스너를 제거한다.

포그라운드 복구 작업 순서는 다음과 같다.

1. `adoptNativeLocationSessionTokens()`로 기존 세션 안전 규칙에 따라 네이티브·WebView 토큰을 조정한다.
2. 세션이 실제로 채택됐으면 `syncFromSession()`으로 Auth 상태를 갱신한다.
3. 세션이 바뀐 경우 브라우저 task queue를 한 번 넘겨 Auth 재렌더 기회를 준 뒤, effect가 아직 유효한지 확인한다.
4. `queryClient.refetchQueries({ type: "active" }, { cancelRefetch: true })`로 현재 관찰 중인 query만 재조회한다.

`refetchQueries`는 데이터 조회만 대상으로 하므로 mutation을 실행하지 않는다. 기존 요청이 백그라운드에서 멈춘 경우 새 조회가 이를 대체할 수 있도록 기본 취소·재조회 정책을 사용한다. 이미 표시 중인 캐시 데이터는 유지된다.

### 3. focusManager를 사용하지 않는 이유

TanStack Query 5.101.2의 `QueryClient`는 `focusManager`가 활성화될 때 `resumePausedMutations()`도 호출한다. 네이티브 복귀 신호를 `focusManager.setFocused(true)`에 직접 연결하면 사용자가 버튼으로 시작해야 하는 mutation을 앱 복귀만으로 재개할 가능성이 생긴다.

따라서 이번 변경은 `focusManager`를 건드리지 않고 `queryClient.refetchQueries({ type: "active" }, { cancelRefetch: true })`만 직접 호출한다. 이로써 현재 화면의 읽기 전용 query는 갱신하면서 결제·AI·원격제어 자동 실행 가능성을 차단한다.

## 오류 처리

- 세션 채택 실패는 기존 함수의 보수적 처리대로 현재 세션을 삭제하지 않는다.
- 생명주기 리스너 등록 또는 복구 작업의 예외는 콘솔에 진단 가능한 한 줄을 남기고 기존 캐시 화면을 유지한다.
- 한 query의 실패가 앱 전체 새로고침이나 다른 query 캐시 삭제로 이어지지 않는다.
- 로그아웃 또는 컴포넌트 정리 이후 늦게 끝난 비동기 작업은 재조회를 시작하지 않는다.
- 세션이 바뀐 경우 Auth 반영 뒤 활성 query를 조회해 이전 사용자 컨텍스트 재사용 가능성을 낮춘다.

## 테스트 설계

### 자동 회귀 테스트

`tests/nativeQueryResume.test.ts`에서 다음을 검증한다.

- 최초 `active` 상태에서는 추가 조회가 없다.
- `inactive`만으로는 조회가 없다.
- `inactive -> active` 전환에서 정확히 한 번 실행된다.
- 중복 `active` 이벤트가 실행 횟수를 늘리지 않는다.
- 실행 중 중복 이벤트가 동시 작업을 만들지 않는다.
- 정리 이후 이벤트는 실행되지 않는다.
- 세션 채택, Auth 동기화, 활성 query 재조회 순서가 보장된다.
- 재조회 필터가 `type: "active"`이고 mutation 실행 경로가 없다.

기존 세션·위치 회귀 테스트와 함께 `npm run typecheck`, 전체 Node 테스트, `npm run build`를 실행한다.

### 실기기 검증

- S25 부모 앱의 실시간 위치 및 오늘 경로 화면을 각각 연 상태에서 앱을 백그라운드로 보낸다.
- 백그라운드 동안 razr의 서버 위치 `updated_at`이 증가한 사실을 확인한다.
- S25를 아이콘 또는 최근 앱 화면으로 직접 복귀하고 별도 강제 새로고침 없이 최신 시각·경로가 갱신되는지 CDP와 화면으로 확인한다.
- 동일 전환을 두 번 반복해 중복 요청 폭증이나 화면 초기화가 없는지 확인한다.
- razr의 아이 세션, 페어링, 위치 서비스가 그대로 유지되는지 확인한다.
- 연결된 다른 부모 검증기가 있으면 같은 시나리오를 추가 실행한다.

## 배포와 변경 보호

- 관련 테스트와 빌드가 모두 통과한 뒤 `npx cap sync android`와 Android debug APK 빌드를 수행한다.
- `adb install -r`만 사용해 연결된 검증 기기에 설치하며 앱 데이터와 세션을 삭제하지 않는다.
- 설치 후 버전·화면·API 응답을 다시 확인한다.
- 이번 작업 파일만 스테이징하고 기존 `TeacherStudents` 변경, 빌드 캐시, 임시 스크립트 및 출력물은 커밋에서 제외한다.
- 새로 확인한 운영 규칙은 `AGENTS.md`와 `CLAUDE.md`에 동일하게 반영한다.

## 완료 기준

자동 테스트와 빌드 통과만으로 완료하지 않는다. S25에서 백그라운드 후 일반적인 사용자 복귀 동선으로 실시간 위치와 오늘 경로가 최신 서버 시각으로 갱신되고, razr 세션·위치 서비스가 유지된 관측 증거가 있어야 완료다.
