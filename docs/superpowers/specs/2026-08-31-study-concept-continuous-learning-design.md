# 수학 세부 개념 선택과 자유 연속 학습 설계

## 목표

혜니캘린더의 한국 전용 수학 미니앱에서 모든 아이가 학년을 고른 뒤 공식 교육과정의 세부 개념을 다양하게 선택하고, 문제 묶음의 끝을 의식하지 않은 채 원하는 만큼 계속 학습할 수 있게 한다. 보호자가 지정한 학년은 아이가 덮어쓰지 못하지만 학습 접근과 주제 선택은 막지 않는다.

운영 Study 콘텐츠에는 3학년 29개, 4학년 20개, 5학년 25개, 6학년 20개로 총 94개의 세부 개념이 있으며 각 개념에 검증된 문제 변형 36개가 있다. 이 정본을 그대로 사용하고 화면 전용 가짜 분류나 별도 번역 카탈로그를 만들지 않는다.

## 검토한 접근

1. Calendar에 개념 목록을 정적으로 복제한다. 화면 구현은 빠르지만 Study 콘텐츠 릴리스와 쉽게 어긋나므로 사용하지 않는다.
2. 기존 `focus` 미션을 주제 학습으로 재사용한다. `focus`는 오개념 보정 계획과 진행 상태를 전제로 하므로 자유 선택 의미와 충돌한다.
3. Study가 활성 릴리스의 개념 카탈로그와 개념 지정 미션을 제공하고 Calendar가 이를 표시한다. 내부 세션은 안전한 크기로 유지하되 자동으로 다음 세션을 연결한다. 이 방식을 채택한다.

## 아이 화면 흐름

1. 아이 홈에서 `미니앱`을 누르고 미니앱 허브에서 `수학`을 누른다.
2. 학년을 직접 정해야 하는 아이에게 3~6학년 버튼을 보여준다. 누른 학년 버튼 안에서만 로딩 막대가 움직이며 다른 버튼은 움직이지 않는다. 다른 학년을 다시 누르면 현재 선택만 바뀐다.
3. 보호자 생년월일 또는 보호자 override가 정본인 경우 학년은 잠긴 배지로 보여주고 해당 학년 개념 목록으로 바로 이동한다.
4. 개념 화면의 첫 카드는 `골고루 풀기`다. 이어서 `unit_key`로 묶은 모든 세부 개념 카드를 순서대로 보여준다. 각 카드에는 개념명과 준비된 문제 수를 표시한다.
5. `골고루 풀기`는 현재 적응형 배정을 유지한다. 세부 개념 카드는 정확히 그 개념의 문제만 배정한다.
6. 문제 화면에는 `8문제 중 N번째`나 완료 묶음을 표시하지 않는다. 선택한 개념명 또는 `골고루 풀기`, `계속 학습 중`만 보여준다.
7. 내부 세션의 마지막 문제에서 `다음 문제`를 누르면 같은 선택으로 새 세션을 자동 생성해 첫 문제로 이어진다. 아이에게 완료 화면이나 묶음 제한을 노출하지 않는다.
8. `주제 바꾸기`를 누르면 현재 세션의 풀지 않은 문제만 `abandoned`로 닫고 이미 푼 기록은 보존한 뒤 개념 목록으로 돌아간다. 그곳에서 학년도 다시 선택할 수 있다.
9. 홈으로 나가거나 앱을 다시 열었을 때 활성 세션이 있으면 선택 개념과 함께 정확히 이어서 푼다. 완료된 캐시 세션은 최신 learner readback 전에는 복원하지 않는다.

## Study 데이터와 배정

- 활성 `content_releases`의 `concepts`와 `problems`를 기준으로 학년별 카탈로그를 만든다.
- 카탈로그 항목은 `conceptId`, `unitKey`, `title`, `problemCount`만 반환한다. 정답·해설·내부 문제 ID 목록은 노출하지 않는다.
- `learning_sessions`에 nullable `selected_concept_id`를 추가한다. null은 적응형 `골고루 풀기`, 값이 있으면 세부 개념 학습이다.
- 세부 개념 배정은 선택 학년과 선택 개념이 모두 일치하는 후보만 사용한다. 최근 16개 문제와 동일 정규화 문항을 우선 제외하고, 36개 풀을 회전시켜 반복 노출을 늦춘다. 가용 후보가 부족하면 오래된 노출부터 다시 허용하되 같은 세션 안 중복은 금지한다.
- 내부 세션은 기존 쓰기 원자성, 피로도, 제출 멱등성, 부모 리포트 호환을 위해 8문제로 유지한다. 이는 저장 구현 세부사항이며 UI 계약에는 포함하지 않는다.
- 주제 변경은 세션과 미해결 `session_problem_states`를 하나의 D1 batch로 `abandoned` 처리한다. 이미 완료된 시도·개념 진도·보상은 되돌리지 않는다.
- migration 0009가 `selected_concept_id`와 조회 인덱스를 추가하고 schema version을 9로 올린다.

## Calendar와 Study 계약

기존 API 버전 문자열은 유지한다. 아래 변경은 additive이며 Study를 먼저 배포하면 구 Calendar Worker도 계속 동작한다.

- `GET /api/study/learner/concepts?grade=3..6`
- `POST /api/study/learner/missions` body에 선택적 `conceptId`
- `POST /api/study/learner/missions/:missionId/abandon`
- 미션 DTO에 `selection: { kind: "adaptive" } | { kind: "concept", conceptId, title }`
- Service Binding에 `getCalendarConcepts`, `abandonCalendarMission`과 이에 대응하는 좁은 HMAC operation을 추가한다.

Calendar는 현재 membership, KR market, child member, 학년 정본을 기존 방식으로 매 요청 재검증한다. 학년 정본이 없는 경우 카탈로그와 미션 시작 요청의 선택 학년을 서명 fingerprint에 포함한다. `conceptId`는 길이와 NFC 형식을 검사하고 Study가 활성 릴리스·선택 학년 소속을 다시 검증한다.

## 성능과 오류 처리

- 개념 카탈로그는 학년별 React Query key로 캐시하고 화면 재진입 시 백그라운드 갱신한다.
- 학년 로딩은 `pendingGrade`와 일치하는 버튼에만 표시한다. 전체 버튼의 `aria-busy`를 동시에 켜지 않는다.
- 미션 시작과 제출의 성공 응답을 기다리는 동안 관련 없는 learner/report 갱신은 계속 백그라운드에서 수행한다.
- 다음 내부 세션 준비 실패 시 현재 설명을 지우지 않고 같은 선택으로 `다시 시도`, `주제 바꾸기`, `아이 홈`을 제공한다.
- 전역의 어색한 저장 실패 토스트는 Study 시작·제출·중단 mutation에 표시하지 않는다. 해당 화면 안에서 한국어 복구 문구를 표시한다.

## 검증

- Study: 카탈로그가 학년 경계를 지키고 개념당 36개를 보고하는지, 다른 학년 conceptId를 거부하는지, 선택 개념 세션의 모든 문제가 같은 개념인지, 최근 노출 회전과 중복 금지, 중단 batch 원자성, migration/index/schema version을 테스트한다.
- Calendar: 선택한 학년만 busy인지, 94개 정본 DTO를 좁게 파싱하는지, 학년→개념→미션 요청 body가 정확한지, 완료 캐시를 재복원하지 않는지, 마지막 문제 뒤 자동 연속 학습과 주제 변경 오류 복구를 테스트한다.
- 전체 typecheck, Worker tests, Calendar 전체 테스트, 빌드, i18n 검사, Worker dry-run, 브라우저 QA를 통과한다.
- Study migration → Study Worker → Calendar Worker → Pages 순서로 배포하고 원격 schema/version/health/assets를 읽어 확인한다.
- Play 스토어는 갱신하지 않는다. 동일 소스의 별도 Android debug APK를 기존 A17 데이터 위에 `adb install -r`로 설치해 아이 홈→미니앱→수학→학년→여러 세부 개념→연속 문제→주제 변경→재진입을 실기기에서 검증한다.

## 출시 판정

메인 원격 SHA, Cloudflare 활성 버전, Pages asset SHA, A17 세션 보존, 개념 선택 및 연속 학습, 답안·해설 지연 측정이 모두 확인되면 별도 미니앱 출시 가능으로 판정한다. Play 게시 상태는 이 판정과 분리한다.
