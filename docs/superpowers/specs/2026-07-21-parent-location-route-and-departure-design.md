# 부모 오늘 경로·머문 곳·출발 알림 개선 설계

- 작성일: 2026-07-21
- 대상 저장소: `hyeni-3` 앱, `hyeni-1/worker` 백엔드, `hyeni-1` 레거시 상태머신 parity
- 상태: 설계안 승인 완료, 작성 문서 사용자 검토 대기

## 1. 목표

부모가 오늘 경로 화면에서 아이의 하루 이동 순서와 머문 곳을 빠르게 읽고, 원하는 시각에 아이가 어디에 있었는지 기록의 한계까지 포함해 정확히 확인할 수 있게 한다.

등록 장소 출발 알림은 GPS 경계 흔들림 방어를 유지하면서, 정확한 위치가 장소에서 충분히 멀어진 경우에는 기존보다 빠르게 확정한다.

## 2. 확인된 문제와 근거

### 2.1 오늘 경로 정보가 분리되어 있다

현재 `ParentLocation`의 오늘 경로는 다음 정보가 서로 떨어져 있다.

- 지도 위 경로·마커
- 상단의 별도 시간 선택 카드
- 하단의 오늘 머문 곳 목록

사용자는 시간을 움직인 뒤 지도 마커만 보고 당시 장소를 해석해야 한다. 선택 시각, 실제 위치 기록 시각, 장소명, 머문 상태가 한곳에 모이지 않아 특정 시각의 위치를 빠르게 판단하기 어렵다.

### 2.2 머문 곳 목록이 이동 순서를 충분히 드러내지 않는다

현재 목록은 개별 행의 장소명·시각·체류시간은 제공하지만, 각 장소가 하루 여정에서 어떤 순서로 이어지는지 시각적 연결이 약하다. 선택한 시간과 목록 항목의 대응도 자동으로 드러나지 않는다.

### 2.3 지도 중심과 아이 마커 좌표가 결합되어 있다

`KakaoMap`은 명시적 `center`가 전달되면 `centerLatLng`를 지도 중심뿐 아니라 자녀 오버레이 위치에도 사용한다. 머문 곳을 선택해 지도 중심을 옮길 때 실제 선택 시각의 아이 위치와 무관하게 아이 마커까지 머문 곳 중심으로 이동할 수 있다.

지도 중심과 데이터 마커 좌표를 분리해야 한다.

### 2.4 등록 장소 출발 판정의 고정 180초가 지연을 만든다

운영 D1의 최근 등록 장소 출발 기록을 위치 이력과 대조한 결과는 다음과 같다.

- 50m 밖 첫 신뢰 가능한 위치: 2026-07-20 20:52:37 KST
- 100m 밖 신뢰 가능한 위치: 2026-07-20 20:53:15 KST
- 출발 알림 생성: 2026-07-20 20:55:51 KST
- 첫 50m 이탈부터 알림까지: 약 3분 13초

현재 Worker·Android 상태머신은 장소에서 얼마나 멀리 이동했는지와 위치 정확도를 구분하지 않고, 이탈 반경 밖 첫 fix 이후 항상 180초를 기다린다. 운영 기록의 지연은 이 고정 타이머와 일치한다.

## 3. 확정한 제품 방향

### 3.1 시각 원칙

시각 논제는 “지도는 넓고 조용하게, 정보는 하나의 여정 시트에서 읽기 쉽게”이다.

- 지도는 경로와 공간 관계를 보여주는 주 작업면으로 유지한다.
- 시간 선택과 머문 곳은 하나의 하단 여정 시트로 통합한다.
- 개별 카드를 쌓지 않고 번호·연결선·텍스트 위계로 하루 흐름을 만든다.
- 기존 디자인 토큰, 플레인 CSS, 기존 Kakao 지도와 3D/lucide 아이콘 언어만 사용한다.

### 3.2 선택된 레이아웃

사용자가 선택한 안은 `B. 여정 시트`다.

여정 시트의 정보 순서는 다음과 같다.

1. `오늘의 이동`
2. `08:00부터 · 머문 곳 N곳`
3. 현재 선택 시각
4. 선택 시각의 위치 결과
5. 시간 눈금
6. 머문 곳 세로 타임라인

### 3.3 선택된 시간 탐색 방식

사용자가 선택한 방식은 `2. 시간 눈금 중심`이다.

- 오전 8시부터 현재까지를 하나의 시간 축으로 표시한다.
- 시간대 바로가기 칩으로 긴 범위를 빠르게 이동한다.
- range 입력은 1분 단위로 움직인다.
- 선택 시각은 항상 텍스트로 크게 표시한다.
- 시간 선택기나 ±10분 버튼은 추가하지 않는다.
- 현재 시각으로 돌아가는 동선은 시간 축의 끝 또는 별도 `지금` 칩으로 제공한다.

## 4. 오늘 경로 데이터 설계

### 4.1 선택 시각 스냅샷

새 순수 변환 모듈이 다음 입력을 받는다.

- 선택한 자녀의 시간순 위치 이력
- 선택 시각
- 검출된 머문 곳 목록

반환 결과는 다음 상태를 구분한다.

- `no_previous_record`: 선택 시각 이전 위치 기록 없음
- `reliable`: 75m 이하 정확도의 실제 fix
- `low_accuracy`: 정확도 미보고 또는 75m 초과 실제 fix
- `estimated`: `is_estimated` 위치

위치점 선택 규칙은 다음과 같다.

1. 선택 시각보다 미래인 점은 사용하지 않는다.
2. 선택 시각 이하의 마지막 점만 사용한다.
3. 실제 기록 시각과 선택 시각의 차이를 함께 계산한다.
4. 5분을 초과하면 현재 위치처럼 표현하지 않고 기록 공백 상태로 강등한다.

### 4.2 장소명 결정

표시 우선순위는 다음과 같다.

1. 선택 시각이 머문 곳의 `[arrivalMs, departureMs]`에 포함되면 그 머문 곳 라벨
2. 저장 장소 200m 이내 매칭
3. 선택한 신뢰 가능한 fix 한 점에 대한 Kakao 역지오코딩
4. 역지오코딩 실패 시 `장소명을 확인하지 못했어요`

저정확도·추정 위치는 구체 장소를 확정하지 않는다.

- 저정확도: `정확도가 낮은 위치 기록`
- 추정 위치: `실제 위치 사이의 추정 구간`

### 4.3 사용자 문구

신뢰 가능한 머문 위치 예시:

- `15:00 · 학교에 머무름`
- `14:58에 확인된 위치`

신뢰 가능한 이동 위치 예시:

- `15:20 · ○○로 근처 · 이동 중`
- `15:18에 확인된 위치`

기록 공백 예시:

- `15:20 기준 마지막 기록`
- `12분 전 위치 기록이에요`

선택 시각 이전 기록이 없는 경우:

- `이 시간 이전의 위치 기록이 없어요`

## 5. 화면·상호작용 설계

### 5.1 여정 시트

- 기존 하단 시트 드래그 접기·펼치기를 유지한다.
- 헤더와 목록을 드래그해 아래로 접을 수 있다.
- 접힌 상태에는 `오늘의 이동 · N곳` 재열기 버튼을 표시한다.
- 목록은 개별 배경 카드 대신 세로 연결선과 순번 원형으로 구성한다.
- 각 행은 장소명, 도착–출발 시각, 체류시간 배지를 표시한다.
- 전체 행은 최소 44px 터치 영역과 `hy-press` 피드백을 갖는다.

### 5.2 시간 눈금

- 시간대 칩은 현재 윈도우에 포함되는 시각만 생성한다.
- 새벽 00–07시는 기존 계약대로 전날 오전 8시부터 이어진다.
- 칩을 누르면 해당 정시로 이동한다.
- range 입력은 1분 단위이며 `aria-label`에 선택 시각을 포함한다.
- 시간 이동 중 경로, 자녀 마커, 결과 문구를 같은 React 상태에서 갱신한다.
- `prefers-reduced-motion`에서는 시트·강조 전환을 즉시 적용한다.

### 5.3 머문 곳 연동

- 선택 시각이 머문 곳 범위 안이면 해당 타임라인 행과 지도 마커를 자동 강조한다.
- 머문 곳 행을 누르면 해당 마커를 지도 중심으로 이동한다.
- 이 지도 중심 이동은 선택 시각의 자녀 마커 좌표를 변경하지 않는다.
- 같은 행을 다시 누르면 머문 곳 중심 고정을 해제한다.

### 5.4 지도 표시

- 경로는 선택 시각까지 자른다.
- 실제 구간은 실선, 추정 구간은 기존대로 점선이다.
- 자녀 마커는 선택 스냅샷의 좌표에만 표시한다.
- 스냅샷이 없으면 자녀 마커를 표시하지 않는다.
- `KakaoMap`의 명시적 지도 중심과 자녀 오버레이 좌표를 분리한다.

## 6. 등록 장소 출발 알림 설계

### 6.1 적응형 판정

기존 180초 타이머를 완전히 제거하지 않는다. 다음 조건을 모두 만족하는 확실한 이탈에만 60초 타이머를 적용한다.

- 위치 fix 정확도 `accuracy <= 30m`
- 장소별 계산 이탈 반경보다 `30m` 이상 더 멀리 있음
- 이탈 반경 밖 상태가 첫 이탈 fix부터 계속 유지됨

그 외에는 기존 180초를 유지한다.

### 6.2 시간 계산

빠른 판정의 경과 시간은 `departureArmedAtMs`부터 계산한다.

예를 들어 경계 밖 첫 fix 이후 40초가 지나 확실한 원거리 이탈 fix가 들어오면, 추가로 60초를 다시 기다리지 않는다. 첫 이탈부터 누적 60초를 넘었으면 그 원거리 fix에서 출발을 확정한다.

### 6.3 취소·중복 규칙

- 확인 중 장소 안으로 돌아오면 기존처럼 `DEPARTURE_CANCELLED`로 타이머를 지운다.
- `SILENT_RE_ENTER`와 `SILENT_LEAVE` 불변식을 유지한다.
- 10분 쿨다운, 배치 도착 병합, 15분 늦은 출발 억제를 유지한다.
- 기존 멱등키와 상태 테이블을 유지한다.
- D1 스키마 변경은 없다.

### 6.4 parity 대상

다음 세 구현의 상수와 분기 결과를 일치시킨다.

- `hyeni-1/worker/shared/registeredPlaceGeofence.js`
- `hyeni-3/android/app/src/main/java/com/hyeni/calendar/GeofenceStateMachine.java`
- `hyeni-1/src/lib/registeredPlaceGeofence.js`
- `hyeni-1/src/lib/locationConstants.js`

활성 Android 배포는 `hyeni-3`를 사용한다. 레거시 JS는 상태머신 계약 드리프트를 막기 위해 함께 갱신한다.

## 7. 오류·빈 상태

### 7.1 오늘 경로

- 위치 이력 loading/error/empty 상태를 기존처럼 분리한다.
- 조회 실패 시 캐시 경로를 표시하지 않고 재시도 동선을 유지한다.
- 선택 시각 역지오코딩 실패가 전체 경로를 오류로 만들지 않는다.
- 위치 결과는 `장소명을 확인하지 못했어요`로 강등하고 지도 좌표와 실제 기록 시각은 유지한다.

### 7.2 출발 알림

- 정확도 미보고 fix는 빠른 판정에 사용하지 않는다.
- 정확도 30m 초과 75m 이하 fix는 기존 180초 판정에는 사용할 수 있다.
- 정확도 75m 초과 fix는 기존 상태머신과 동일하게 무시한다.
- Worker 전달 실패 시 상태를 진행하지 않고 기존 멱등키로 재시도한다.

## 8. 테스트 전략

### 8.1 앱 변환 테스트

테스트를 먼저 추가해 다음을 실패시키고 구현 후 통과시킨다.

- 선택 시각보다 미래인 위치점을 사용하지 않는다.
- 선택 시각 이하 마지막 위치점을 고른다.
- 기록 차이가 5분을 넘으면 공백 상태가 된다.
- 머문 시간 안의 시각은 해당 머문 곳과 매칭된다.
- 저정확도·추정 위치는 장소를 확정하지 않는다.
- 오전 8시 기준과 새벽 전날 윈도우가 유지된다.

### 8.2 UI·지도 회귀 테스트

- 별도 상단 시간 카드가 제거되고 여정 시트 안에 시간 눈금이 존재한다.
- 세로 타임라인에 장소·시각·체류시간이 렌더된다.
- 시간대 칩과 range 입력에 접근성 이름이 있다.
- `KakaoMap`의 자녀 오버레이가 `center`가 아니라 `child.lat/lng`를 사용한다.
- 접기·펼치기와 드래그 클릭 방지 회귀가 유지된다.

### 8.3 출발 상태머신 테스트

Worker·Android·레거시 JS에 같은 시퀀스를 둔다.

- 정확도 30m 이하이며 이탈 반경보다 30m 이상 멀면 60초 후 `LEAVE`
- 확실한 이탈이어도 60초 전에는 `OUTSIDE_PENDING_TIMER`
- 경계 부근은 180초 유지
- 정확도 30m 초과는 원거리여도 180초 유지
- 타이머 중 장소 안 복귀 시 `DEPARTURE_CANCELLED`
- 조용한 재진입 에피소드는 빠른 조건에서도 `SILENT_LEAVE`

- `npm run typecheck`
- `npm run build`
- Worker: `npx tsc --noEmit`
- Worker 전체 테스트: `C:\Users\TK\Desktop\hyeni-1`에서 `node --test worker/tests/*.test.mjs`
- Android: 관련 JVM 테스트, `lintDebug`, `assembleDebug`
- 모바일 브라우저 390×844에서 오늘 경로 렌더·시간 이동·시트 드래그·수평 오버플로·콘솔 오류 확인
- A17 `RFKL40DP73J` 한 대에만 `adb install -r`로 설치하고 부모 세션을 보존한 채 화면을 확인

아이 역할 동작은 Android 계측/JVM 테스트와 브라우저 역할 검증으로 확인한다. A17에서 로그아웃·역할 전환·재페어링하지 않으며 razr와 S25에는 adb 접근하지 않는다.

## 9. 배포·문서화

- 앱 변경은 `hyeni-3`에 커밋·푸시한다.
- Worker와 레거시 parity 변경은 `hyeni-1`에 커밋·푸시한다.
- Worker 검증 후 프로덕션 Worker를 배포한다.
- 앱 빌드 후 Cloudflare Pages를 `.env`가 없는 임시 디렉터리에서 배포한다.
- 최신 APK를 A17에 `adb install -r`로 설치한다.
- 새 운영 규칙과 검증 근거를 `AGENTS.md`와 `CLAUDE.md`에 함께 반영한다.
