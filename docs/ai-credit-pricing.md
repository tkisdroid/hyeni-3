## 1. 원가 근거

**모델**: `gpt-5.6-luna` — 입력 $0.20/1M, 출력 $1.20/1M (2026-07-30 80% 인하 후 단가).

**실측**(2026-08-17, 프로덕션 Worker 로그 7건 평균):

| 항목 | 값 |
|---|---|
| 입력 토큰 | 2,944 |
| 출력 토큰 | 35 |
| 합계 | 2,979 |
| 지연 | 1.6초 |

입력이 출력의 84배다. 아이 대화는 답이 짧고, **매 turn 실려 나가는 맥락이 원가의 거의 전부**다
(시스템 프롬프트 + 최근 14턴 + 요약 5건 + 장기기억 30건 + 오늘 일정).
→ 대화가 길어져도 원가는 거의 안 늘고, **맥락 설정을 키우면 전 대화의 원가가 함께 오른다.**
`ai-child-chat.ts` 의 `LIMIT 14` / `LIMIT 5` / `LIMIT 30` 을 올릴 때는 이 표를 다시 계산한다.

**환율**: 1 USD = 1,500원(최근 고점 부근을 보수적으로 사용. 실제 8월 중순 ≈ 1,415원).

| 가정 | 입력 | 출력 | 회당 원가 |
|---|---|---|---|
| 실측 | 2,944 | 35 | 0.95원 |
| 최악(기억·일정 증가) | 6,000 | 200 | 2.16원 |
| **계획 원가** | — | — | **3원** |

계획 원가 3원은 최악 가정의 약 1.4배다. 재시도·선제 대화·아이 모니터 호출까지 이 안에 넣는다.

## 2. 가격 설계 의도

**회당 단가를 구독보다 비싸게 둔다.** Premium 4,900원/월은 하루 20회 × 30일 = 600회로 **회당 8.2원**이다.
크레딧은 50~63원/회로 **6~7.7배 비싸다.** 의도된 격차다 —

- 크레딧은 "오늘 더 하고 싶다"를 즉시 푸는 **편의 상품**이지 주력 상품이 아니다.
- 80회 4,400원이 구독 4,900원 바로 아래에 붙어 있어, 부모가 두 값을 비교하면 **구독이 명백히 낫다.**
  구독 전환은 LTV 가 크레딧 단발 구매보다 훨씬 크므로 이 유도가 이득이다.
- 200회 9,900원은 구독을 원치 않는 가족을 위한 최선의 단가(50원/회)다.

**구독도 손해가 나지 않는다.** 구독자가 한 달 600회를 전부 써도 원가 1,800원 vs 순수익 3,786원(수수료 15%)
→ 마진 52%. 최대 사용 시나리오에서도 안전하다.

## 3. 적용 절차

### 3-1. Google Play Console — **사용자(TK)가 직접 해야 한다**

에이전트는 Play Console 가격을 바꿀 수 없다. 다음을 수동으로 설정한다.

1. Play Console → 수익 창출 → 인앱 상품
2. 아래 상품의 **대한민국 가격**을 설정한다.

| productId | 가격 |
|---|---|
| `hyeni_ai_credits_30` | ₩1,900 |
| `hyeni_ai_credits_80` | ₩4,400 |
| `hyeni_ai_credits_200` | ₩9,900 |

3. 저장 후 **활성** 상태를 확인한다.

⚠️ 앱이 표시하는 금액은 Play 가 내려주는 `formattedPrice` 가 정본이다(코드에 금액을 하드코딩하지 않는다).
따라서 Play Console 만 바꾸면 앱 재배포 없이 새 가격이 반영된다.

### 3-2. Worker(웹·PWA Toss 결제 경로)

Toss 결제는 **현재 비활성**이다(`TOSS_PAYMENTS_CLIENT_KEY`/`SECRET_KEY` 미설정 → `readWebAiCreditTossConfig` 가 null).
금액만 미리 맞춰 두었으므로, 나중에 Toss 키를 넣는 순간 Play 와 같은 가격으로 열린다.

```

TOSS_AI_CREDIT_80_AMOUNT_KRW=4400
TOSS_AI_CREDIT_200_AMOUNT_KRW=9900
```

## 4. 크레딧 차감 기준 (2026-08-17 TK 결정)

**아이가 보낸 말 1회 = 1크레딧.** 서버가 LLM 을 실제로 불렀는지와 무관하다.

이전에는 "LLM 호출 여부"로 갈랐다. 그러면 같은 한 마디가 어떤 날은 깎이고 어떤 날은 안 깎여
남은 횟수를 예측할 수 없었고, 내부 구현이 바뀔 때마다 과금이 조용히 따라 움직였다.
이제 화면의 "오늘 N번 더"가 곧 **실제로 말을 걸 수 있는 횟수**다.

예외는 두 가지뿐이며 둘 다 과금 취향이 아니라 원칙이다(`worker/shared/aiUsagePolicy.js`).

| 예외 | 이유 |
|---|---|
| 안전 위험 감지(medium/high) | 힘든 아이가 도움을 청한 turn 에 횟수를 물리지 않는다. 한도가 0이어도 대화가 열린다. |
| 거절만 한 turn·도구 실패 | 해 준 것이 없는데 횟수를 가져가면 아이가 "말 걸면 손해"라고 배운다. |

차감이 늘어난 만큼 원가도 늘지 않는다 — 결정적 응답(일정 조회·설정 변경)은 LLM 을 부르지 않으므로
**그 turn 의 실제 원가는 0원**이다. 위 마진표는 전 turn 이 LLM 을 부른다는 가정이라 실제보다 보수적이다.

## 6. GPT Live(Realtime 음성) 검토 — 2026-08-17

"아이가 AI 친구와 GPT Live 로 대화하면 가격이 어떻게 되나"에 대한 답.
**결론: 지금 구조를 대체하면 안 된다. 도입한다면 분 단위 별도 상품으로만 판다.**

| live mini (캐시 없음) | 35.3원 | 10,605원 |
| live 2.1 (캐시) | 74.4원 | 22,325원 |
| live 2.1 (캐시 없음) | 149.9원 | 44,957원 |

⚠️ 이 계산은 맥락을 매 turn 2,944토큰 고정으로 뒀다. 실제 Realtime 세션은 대화가 쌓일수록
컨텍스트가 **커지므로** 긴 세션의 실제 원가는 이보다 높다.

**분 단위로 판다면**(마진 85% 목표, VAT·수수료 반영):

|---|---|---|
| live mini (캐시) | 230원 | **2,300원** |
| live 2.1 (캐시) | 650원 | 6,500원 |

### 6-5. 원가 말고도 막는 것 — 안전 파이프라인

지금 아이 대화의 안전 장치는 **전부 텍스트 위에서 돈다.**

- `planChildAgentAction` — 아이 문장을 읽고 도구·의도·안전 위험도를 결정한다
- 부모 설정 가드레일 — 금지 주제·허용 주제·부모 지침
- `ensureChildSafetyReply` — 위험 신호가 있으면 답변에 어른에게 알리라는 문장을 **강제**한다
- 장기기억 추출, 대화 요약
- 콘텐츠 신고 — 저장된 assistant 메시지 id 가 있어야 아이가 신고할 수 있다(스토어 UGC 정책)
- 확인 카드 도구(부모 메시지·일정 변경·전화)

오디오→오디오 직결로 바꾸면 이 중간 텍스트 지점이 사라져 **위 장치를 전부 다시 만들어야 한다.**
아동용 앱에서 이건 원가보다 큰 리스크다.

### 6-6. 권고

1. **기본 경로는 지금 구조를 유지한다.** 기기 STT/TTS 는 원가 0이고 이미 배포돼 있다.
   실측 응답 1.6초라 아이가 기다린다고 느낄 수준이 아니다.
2. **live 를 무료 티어나 구독 기본 제공에 넣지 않는다.** 위 표대로 확실한 적자다.
3. 도입한다면 **`gpt-realtime-2.1-mini` + 프롬프트 캐싱 + 분 단위 별도 상품**으로만 한다.
   10분 2,300원 수준이어야 마진 85%가 나온다.
4. live 세션에는 **하드 상한**(예: 1회 10분, 하루 20분)을 서버에서 강제한다.
   끊기지 않는 세션은 원가가 선형으로 늘어난다.
5. 도입 전에 안전 파이프라인(6-5)을 오디오 경로에서 어떻게 유지할지 먼저 설계한다.

## 7. 무제한 가족 (운영자 본인 계정) — 2026-08-17 TK 지시

운영자 본인 가족은 AI 친구 대화 한도와 차감을 적용하지 않는다.

**판정**: Worker secret `AI_UNLIMITED_OWNER_IDS` 에 적힌 **가족 소유 부모 계정** 목록
(`worker/lib/aiUnlimitedAccess.ts`). 현재 값은 `tkisdroid` 계정
`a41278ce-82f4-4d5d-9285-fd049565827f` 하나이며, 이 계정이 소유한 가족(혜니네 포함)의 아이가 대상이다.

**왜 가족 id 가 아니라 소유 계정인가**: 재페어링·가족 재생성 때마다 secret 을 고치지 않기 위해서다.
소유 계정은 그대로 유지된다.

**왜 DB 가 아니라 secret 인가**: `family_subscription` 이나 `user_tier` 를 조작하면 구독 검증·RTDN
재검증·스토어 결제 정본과 어긋난다. 무제한 판정은 **읽기 전용 SELECT 하나**뿐이고 결제 상태를
전혀 건드리지 않는다(회귀 테스트가 이를 강제한다).

**적용 범위**: 한도 게이트 통과 + 크레딧 차감 생략. 안전 정책·부모 가드레일·도구 권한은 그대로다
(무제한은 과금만 면제하지 안전을 면제하지 않는다).

**화면**: `/api/ai/child-chat` 과 `/api/ai/credits/public-status` 가 `unlimited: true` 를 내려주고
아이 대화 헤더가 남은 횟수 대신 **무제한**을 표시한다. 줄지 않는 숫자는 고장처럼 보이기 때문이다.

**★fail-closed**: secret 이 없거나 비어 있으면 아무도 무제한이 아니다. 조회 실패도 false 로 닫는다.
`unlimited` 는 정확히 boolean `true` 일 때만 무제한으로 읽는다(문자열 `"true"`·`1` 은 거부).

**원가 영향**: 이 가족의 대화는 매출 없이 원가만 발생한다(회당 약 1원). 운영자 1가족이므로
무시할 수준이지만, 목록을 늘리면 늘어난 만큼 그대로 손실이다.
